Config backups

Full GET /config snapshots are captured after a successful Settings save (shown as the last stage in apply progress), before repair pairing when the API is online, or when you click Backup now. If capture fails (slow camera / timeout), the apply progress and the warning above say so — settings may still have been applied. Restore is always explicit and never becomes live desired state.

Restore coverage: backups store the full config JSON (including stream/OSD when the agent returns them), but apply only writes fields the hub can peel onto native /settings/... leaves. Raptor’s omnibus PATCH /config ignores stream/OSD, so those must go through settings paths. The hub peels stream/OSD (including OSD position) from a shared writable-settings catalog onto those leaves. Pairing secrets are never restored.
