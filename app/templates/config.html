Web UI

If both auth fields are set, the web UI uses HTTP Basic Auth. Registration staleness is optional fallback logic for retained MQTT registrations. Snapshot heartbeat actively refreshes each camera preview into the local cache and updates the dashboard badge without removing the camera from the roster. When the camera goes offline, recent cached previews remain visible with a muted treatment until the cached snapshot age exceeds the stale threshold, after which the placeholder is shown instead. Set the heartbeat interval to 0 to disable background refresh. Environment variables HUB_UI_USERNAME and HUB_UI_PASSWORD still override the auth values when present.

History

History is written to a local SQLite database after native actions and probe results. Leave the path empty to use the default database next to the hub config file. Per-camera retention caps trim the oldest rows after inserts so the store stays bounded. This store is for analysis and timelines; live camera control does not read desired state from it.

Static Camera Overrides

Use YAML for optional aliases, snapshot settings, and ONVIF credentials. Auto-registered cameras still appear on the dashboard even if they are not listed here.

Supported per-camera keys include name, ip, snapshot_url, api_key, api_base_url, api_token, onvif_endpoint, onvif_username, and onvif_password.
