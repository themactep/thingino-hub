Before you migrate

After a full OTA the camera often loses MQTT broker settings and gets a new MQTT identity. Migrate only moves hub history/backups. Reconnecting requires MQTT on the camera first, then hub pairing, then config restore.

  1. 1. On the camera Web UI — MQTT
    Where: {% if offer.live_web_ui_url %} {{ offer.live_web_ui_url }} {% else %} http://{{ offer.ip }}/ {% endif %} → settings for MQTT / broker (login usually thingino / thingino).
    What: enter this hub’s MQTT broker {% if offer.mqtt_broker_host %} ({{ offer.mqtt_broker_host }}{% if offer.mqtt_broker_port %}:{{ offer.mqtt_broker_port }}{% endif %}) {% else %} host/port {% endif %} and credentials, enable the camera MQTT client, then save. When: the live camera shows up again on this hub’s MQTT roster. OTA often wipes these settings — this is usually why the camera “disappears” after update.
  2. 2. On this hub — migrate
    Click Continue below to move history/backups onto the live identity and remove the stale one.
  3. 3. On this hub — Connect, then Install Pairing Bundle
    Open {{ offer.live_name }} and finish Connect → Install Pairing Bundle so the hub can push the native API token over MQTT.
  4. 4. If Native API is still offline — camera Web UI Hub Pairing
    Where: camera → Services → Hub Pairing. What: paste the hub token from Install Pairing Bundle / Show Pairing Details, save, restart the agent. When: hub shows Native API online.
  5. 5. Restore config
    Only after API is online: Config Backups → Review restore. Pairing/MQTT secrets are never restored from backups.
